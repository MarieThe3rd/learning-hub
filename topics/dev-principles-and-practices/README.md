# ✨ Dev Principles and Practices

Master Clean Code, Object-Oriented Programming, SOLID principles, and Design Patterns — the foundation of professional software development.

## 🎯 Learning Goals

- [ ] Write clean, readable, and self-documenting code
- [ ] Apply the SOLID principles in real code
- [ ] Identify and refactor common code smells
- [ ] Understand and apply the core OOP pillars (encapsulation, inheritance, polymorphism, abstraction)
- [ ] Recognise and implement key design patterns (creational, structural, behavioural)
- [ ] Apply DRY, YAGNI, and KISS principles in daily coding
- [ ] Write code with testability in mind
- [ ] Conduct and receive constructive code reviews

## 🗺️ Learning Path

### Stage 1: Clean Code Fundamentals
- Meaningful naming for variables, functions, and classes
- Writing small, focused functions that do one thing
- Avoiding magic numbers and unexplained strings
- Comments: when they help vs. when they hide poor code
- Consistent formatting and code organisation

### Stage 2: Object-Oriented Programming
- Encapsulation — hiding implementation details
- Inheritance — when to use it and when to prefer composition
- Polymorphism — designing for extensibility
- Abstraction — coding to interfaces, not implementations
- Composition over inheritance

### Stage 3: SOLID Principles
- **S** — Single Responsibility Principle
- **O** — Open/Closed Principle
- **L** — Liskov Substitution Principle
- **I** — Interface Segregation Principle
- **D** — Dependency Inversion Principle

### Stage 4: Code Smells & Refactoring
- Common code smells: long method, large class, feature envy, data clumps
- Safe refactoring techniques (with test coverage)
- The boy scout rule: always leave code cleaner than you found it
- Refactoring vs. rewriting — making the right call

### Stage 5: Design Patterns
- **Creational**: Factory Method, Abstract Factory, Builder, Singleton (and why to use it sparingly)
- **Structural**: Adapter, Decorator, Facade, Proxy
- **Behavioural**: Strategy, Observer, Command, Template Method, Chain of Responsibility
- Recognising patterns in existing frameworks and libraries

### Stage 6: Testing Principles
- Why testability is a design quality
- TDD basics — red, green, refactor
- Unit vs. integration vs. end-to-end tests
- Test doubles: mocks, stubs, fakes
- Writing readable, maintainable tests
